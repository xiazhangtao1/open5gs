## 现场释放操作及已知边界

会话释放：现场 N2 与 PFCP 回复成功，TShark 从现场采集数据独立解出 `NAS-5GSM PDU session release command`（`0xd3`）、PSI `1`、正常释放原因 `36`。未观察到 UE 的 NAS Release Complete；约 30 秒保护清理后，UE 仍注册、目标 PDU 会话消失。

释放后注册 UE 数为 6、PDU 会话数为 5；其他五 UE 各 `50/50` ping 成功。本次现场覆盖单用户单会话释放及跨用户隔离，不能扩展解释为现场已覆盖同一 UE 多 PDU 会话隔离。

用户释放：OAI UE 日志明确收到 NAS 去注册请求，但未返回对应 NAS 接受消息；AMF 经超时清理，NGAP 释放完成。不能记录为现场 NAS 去注册完整闭环通过，仍需结合 OAI 版本和状态机继续定位。

UE 105 重连后曾出现 UL iperf `server busy`，同时 ping 与 DL 正常。仅使用 `ss -K` 关闭测试服务器 `15220` 端口面向 UE 105 的遗留 UDP socket 后，UL 恢复；未重启或修改核心网。该次故障证据指向测试工具遗留状态，不能归因为核心网转发故障，也不能替代对其他异常的逐项分析。

恢复记录显示 UE 105 已连接，UL 约 `3.03 Mbps`、DL 约 `6.13 Mbps`；最后恢复日志记录 UL `3.09 Mbps`、DL `6.14 Mbps`、用户数为 6。
