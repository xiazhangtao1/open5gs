# WebUI 会话与用户控制

登录管理员账户后，在「会话」中点击终端 SUPI，展开「管理此会话」。可查询当前专载、建立专载、修改 QoS / 过滤规则、删除专载，以及释放该 PDU 会话。终端注册与其他会话保留。在「终端」详情中可释放单个用户；列表上方「用户管理」可预览当前用户清单，再逐个释放全部用户。

这里的默认承载对应 5G PDU 会话的默认 QoS Flow。删除默认流采用**释放整个 PDU 会话**，不提供单独删除默认 QFI。默认 QoS / Session-AMBR 的在线修改属于后续阶段；本次不修改签约数据库，不由网页主动建立默认会话。

## 规则用途与展示

会话详情默认显示业务规则，内部辅助规则单独折叠；规则列表提供「业务规则 / 内部辅助规则 / 全部规则」筛选。未设置的 QFI、5QI 和未关联的 QER 显示为 `—`，原始 JSON 仍保留原值。

用途由 PDR 的 Source Interface 与关联 FAR 的 Destination Interface 判断，不根据 QFI=0 或速率=0 推断。控制面与接入侧之间的规则分别显示为控制面下发、终端上送辅助报文，典型用途为 IPv6 路由请求和通告。空闲业务规则仍显示；旧快照缺少接口字段时保留为「用途待确认」，不会误折叠。

接口元数据沿用既有 UPF 规则同步和采样快照路径，每条增加两个 uint8 标量。当前构建中统计槽仍为 88 字节，快照规则仍为 48 字节，利用对齐空间，没有增加结构内存大小。序列化在规则锁外完成，没有新增包处理路径调用或锁，也没有增加采集周期或每浏览者的网元查询。原 `/rates?level=rule` 接口默认仍返回所有规则；网页显式传入 `rule_scope=business|internal|all`，筛选在缓存中、分页前完成。

「在此会话新建专载」只在已有 PDU 会话中新增 QoS Flow；专载接口的 `appSessionId` 是策略侧应用会话标识，不代表新 PDU 会话。新建 PDU 会话需要 UE 发起 NAS 建立流程，网页若要编排「新会话＋专载」，还需接入 UE / 测试仪控制接口并确认新会话实际建立。

新建专载默认过滤规则使用显式 IPv4 CIDR：`permit out ip from 0.0.0.0/0 to assigned` 与 `permit in ip from assigned to 0.0.0.0/0`。编辑已有专载时读取已配置的过滤规则。

AMF 的 cJSON 可能将整数微秒时间戳输出成科学计数法；监控在 JavaScript 安全整数范围内接受数值为整数的浮点表示，再规范化成整数。避免某个 UE 已上报 NCI，却因时间戳表示方式被误判为位置未知。小数、布尔值、非有限值和越界值仍按未知处理；不会根据同基站其他终端猜测小区。

## 执行与结果

- 控制路由为 `/api/core-control`，使用现有登录会话和 CSRF 校验。后端每次从数据库重新读取管理员角色；只读监控令牌不能操作核心网。普通账户也不能通过账户管理接口提升角色。
- PCF、AMF 的上游地址由部署配置固定，浏览器不能传入任意上游地址。没有新增 Pod / 容器。
- 管理表单按用户操作读取当前策略，不随监控轮询查询网元。监控的缓存与只读 JWT 数据路径保持独立。
- 每个会话有随机 `controlVersion`。写入携带 `If-Match: "版本"`；版本变化返回 412，必须重新读取再编辑。PSI 或专载池索引重用不会使旧表单写到新会话。
- 每个 WebUI 进程全局最多 2 个写请求在途、同一 SUPI 最多 1 个，每秒最多 2 个（允许突发 2 个）。并发显式查询最多 16 个。批量释放顺序发送，间隔至少 1 秒；关闭页面或停止按钮会停止后续提交，已发送请求继续执行。
- 每次写入有独立操作编号；相同编号和相同请求返回已有结果，不自动重发到核心网。超时显示「结果待确认」，需核对实时会话及信令。该去重保证受审计集合的容量保留范围约束。
- 「已受理」表示核心网接受执行请求，**不表示终端已经完成信令流程**。专载规则是否生效、会话是否消失，应以实际采集的状态和信令为准。终端被去注册后可能自动重新注册。

## 原生会话释放

PCF 提供本地会话管理接口：

```bash
# 先读取当前版本；专载 API 的查询结果也有 controlVersion。
curl --noproxy '*' --http2-prior-knowledge -sS \
  http://10.2.0.119:30777/xcn-session-control/v1/sessions/imsi-460110000000105/1

# 将返回的 controlVersion 填入，双引号是 If-Match 值的一部分。
curl --noproxy '*' --http2-prior-knowledge -sS -i -X DELETE \
  -H 'If-Match: "<controlVersion>"' \
  http://10.2.0.119:30777/xcn-session-control/v1/sessions/imsi-460110000000105/1
```

没有版本返回 428，旧版本返回 412；已有策略事务时返回 409。当前管理释放支持本地 / LBO 会话，HR 漫游路径返回 501。PCF 经标准 SM Policy termination 通知 SMF；SMF 按 PFCP 删除、NAS PDU Session Release Command 和 N2 资源释放流程执行。空闲终端允许跳过 N1，不重新建立资源；PFCP 删除成功后，等待终端 / 基站释放回复最多 30 秒，再清理网内上下文并记录超时。这是释放流程的等待上限，与监控缓存保留策略无关；它不证明失联终端已收到命令。

旧专载 curl 接口保留兼容性，仍可不带 `If-Match`；网页始终使用版本校验。原生控制接口沿用现有管理网络访问边界，网页的登录与 CSRF 不覆盖直接访问原生端口的请求。

## 资源与审计

SBI 连接复用，单次等待最多 5 秒，响应最多 256 KiB，不自动重试。网页规则请求最多 32 KiB，最多 15 条过滤规则；SMF 策略通知队列最多 32 项。PCF 删除专载的异步回调保存会话标识与专载实例版本，不跨回调保存裸对象指针；SMF 定时器通过会话代际标识查找对象，移除会话时释放定时器。

操作请求和结果写入 MongoDB 的 `core_control_audit` capped collection，最大 16 MiB / 10,000 文档，达到容量时由 MongoDB 淘汰最旧记录。每次操作通常占两条文档；只保存操作摘要和结果，不保存完整信令码流。请求审计写入失败时不执行核心网操作；结果记录失败时会在页面提示保留本次结果。监控采集数据仍留在内存缓存。

UPF 包转发路径没有增加锁、调用或查询；实际释放和专载变更必然需要对应的控制面及 PFCP 操作。50 人浏览仍共享只读缓存，显式管理操作另有限流。当前限速演示和浏览压测的结果不能代表物理链路满负载下的吞吐 / 时延验收。

## 验证

原生隔离测试通过真实 AMF / SMF / PCF / UPF 和受控 NGAP / NAS 对端覆盖双会话隔离、缺少 / 过期版本、PSI 重用、N1 / N2 不同完成顺序、空闲释放、丢失完成回复及另一会话 GTP-U 连通性。专载原有顺序与双会话并发回归保留。WebUI 后端测试覆盖权限、CSRF、幂等、并发和超时；浏览器验证创建、编辑、删除、释放确认、普通用户无权限和手机布局。

Sanitizer 检查保留了原有 NAS 解码 `lib/nas/5gs/ies.c` 对紧凑结构的对齐告警；它不是一次 UBSan 全绿结果。AddressSanitizer 关闭了泄漏检测，关注越界和释放后访问。Sanitizer 网元单独启动，避免旧集成测试框架的子进程退出等待限制；发布构建仍使用标准测试启动和退出流程。

```bash

node webui/server/tests/monitor-test.js
# 在独立核心网测试配置及独立 MongoDB 中执行，勿指向在线业务环境。
XCN_CONTROL_TEST=1 XCN_QOS_PING_IP=10.45.0.1 \
  build/tests/vonr/vonr -q -c build/configs/vonr.yaml dedicated-bearer-test
```
