# NGAP 信令补齐验证（2026-11-04）

补齐已有 AMF 收发路径中的 12 类 NGAP 消息，并对其余成功解码消息增加通用名称采集。网页提供 GNB 身份、SCTP 对端、连接实例、过程码及消息类别；继续复用 ASN.1 树、HEX、搜索、复制和自动刷新。Paging 保留原有 ACTION 摘要，另有携带明确目标 SUPI 的 NGAP 记录。

基站消息显示 `GNB <gnbId>`，没有已确认 ID 时显示 `GNB`。NG Setup 接纳前的上报 ID 仍在摘要及 ASN.1 中保留，不借用其他连接的身份。没有 scope 字段的旧 NG Setup、配置更新和复位记录也按名称识别，不再显示“身份解析中”；该占位文字用于未关联 SUPI 的终端消息，没有固定等待时长。

只完善观测，不扩展 AMF 尚未实现的协议流程。UPF/VPP 转发源代码、锁、采样周期、CPU/CFS、CPU Manager、网络、Pod/容器数量及资源配额保持原配置。`association_id` 为连接生命周期标识，配合 AMF `boot_id`，不使用配置 gNB ID 或 NCI 猜测关联。

## 性能验收与证据

测量使用相同六 UE 流量、升级前后各三轮，每轮每个 UE 发 600 个 ping，间隔 200 ms，并采样实际会话速率。升级后另外运行 50 路浏览读取约 391 秒，共 29,294 次请求，错误为零。停止读取后，再补测一轮；用户面 RTT 来自 UE 独立 ping，网页 API 响应时间不作为用户面性能结论。

| 测量 | 升级前，三轮 | 升级后加 50 路读取，三轮 | 停止读取，一轮 |
| --- | --- | --- | --- |
| Ping 接收 / 发送 | 10,800 / 10,800 | 10,800 / 10,800 | 3,600 / 3,600 |
| 总上行速率，各轮平均 | 10.755–10.782 Mbps | 10.739–10.759 Mbps | 10.765 Mbps |
| 总下行速率，各轮平均 | 21.506–21.508 Mbps | 21.505–21.513 Mbps | 21.511 Mbps |
| UPF CPU，各轮平均 | 0.1137–0.1139 核 | 0.1125–0.1127 核 | 0.1127 核 |
| VPP CPU，各轮平均 | 1.0294–1.0310 核 | 1.0297–1.0305 核 | 1.0303 核 |

每轮保存的下行 iperf 接收端尾部窗口没有报告丢包；不能据此声称所有持续灌包时间均无丢包。UPF/VPP 计数包含真实进程运行，用户面速率包含协议开销，与设定的业务码率略有差异。

| --- | --- | --- | --- | --- |
| 100 | 29.5 ms | 32.7 ms | +3.2 ms | 33.3 ms |
| 101 | 28.9 ms | 32.8 ms | +3.9 ms | 33.2 ms |
| 102 | 29.4 ms | 33.9 ms | +4.5 ms | 32.7 ms |

停止 50 路读取后，RTT 没有恢复到升级前水平，因此这组数据不支持将差异直接归因于浏览请求，也不能证明新版完全没有影响。升级时核心网 Pod 和六个 UE 重建，CPU Manager 为 VPP/UPF 重新分配了 CPU（VPP 从 `48,120` 变为 `49,121`，UPF 也改变），无线仿真状态同样经过重建；未为测试修改 CPU Manager 或固定现场 CPU。旧、新 UPF 的 ELF `.text` SHA256 一致；有读取的三轮中 UPF 未节流，VPP 累计节流约 23 微秒，均不足以直接解释数毫秒差异。

本轮验证了六 UE、约 31.5 Mbps 设定业务流量下的功能、连通性、吞吐稳定和缓存隔离；不替代文档要求的固定条件四组线速/P99 验收。相对既有 5% P99 门槛，本次前后对比未满足，且存在上述环境混杂因素，需要进一步固定条件定位后才能下性能通过结论。

50 路读取期间，UPF 速率和 AMF 信令采样均约 0.5 次/秒、UE/会话约 0.1 次/秒，没有随浏览人数增加。重复查看现场 NG Setup 的请求和响应只触发两次实际解码，没有解析错误或采集丢弃。监控服务内存峰值约 52.7 MiB / 512 MiB，无水位保护、回收或 OOM。
